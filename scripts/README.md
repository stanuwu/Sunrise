# Sunrise dev helper scripts

Optional convenience scripts for building Sunrise from source. Nothing here is
required — every step can be run by hand — but they cut the busywork. Windows
only; run PowerShell scripts from **Windows PowerShell** (`powershell.exe`).

Place this `scripts/` folder at the repo root (next to `Sunrise.sln`), so the
dev-loop script can auto-detect the repo.

## SunriseInstall.ps1 — first-time setup

Checks the toolchain and sets everything up, in re-runnable phases:

| Phase | Does |
| --- | --- |
| 0 | Checks Git, MSBuild/VS, Windows SDK 10.0.26100. Installs Git (winget) automatically; offers the VS Community install (declinable). |
| 1 | Picks/creates the game folder, adds Defender exclusions, downloads DepotDownloader, pulls the game depots. |
| 2 | Backs up the stock DLL, installs the official Sunrise release DLL as a known-good baseline. |
| 3 | Clones the repo, builds Release\|x64, writes `deploy-mybuild.ps1`. |

```powershell
# run elevated (Defender exclusions need admin)
powershell -ExecutionPolicy Bypass -File .\SunriseInstall.ps1
```

Useful flags: `-SkipDepots` (game already downloaded), `-SkipReleaseDll`,
`-SkipBuild`, `-GameDir <path>`, `-SteamUser <login>`,
`-Depot1Manifest`/`-Depot2Manifest` (override stale manifests without editing
the file). A full transcript is written to `<WorkDir>\logs`.

The build forces the 64-bit compiler host (`/p:PreferredToolArchitecture=x64`).
Without it, the build dies with `C1060: compiler is out of heap space` on
`physics_state_runtime.cpp` regardless of system RAM — the 32-bit host is capped
at ~4 GB.

## Sunrise-DevLoop.ps1 — the daily loop

Build → deploy → launch → attach the VS debugger, in one command.

```powershell
.\Sunrise-DevLoop.ps1                # full loop
.\Sunrise-DevLoop.ps1 -BuildOnly     # build + deploy only
.\Sunrise-DevLoop.ps1 -Config Debug  # Debug build (better breakpoints/inspection)
.\Sunrise-DevLoop.ps1 -NoAttach      # don't attach the debugger
.\Sunrise-DevLoop.ps1 -OpenIDE       # open the solution and exit
.\Sunrise-DevLoop.ps1 -Rollback official   # restore the official release DLL
.\Sunrise-DevLoop.ps1 -Rollback vanilla    # restore the stock game DLL
```

First run asks for your Destiny 2 install folder once and saves it to
`sunrise-dev.json` next to the script. The repo root is auto-detected from the
script's location; override with `-RepoDir`/`-GameDir`. MSBuild is located via
`vswhere`, so it survives VS updates and works with any edition.

Debugger attach uses the VS COM automation object and needs Visual Studio
already open with the solution; it retries for ~60s (VS COM is intermittently
busy). If it can't attach, use Debug → Attach to Process → `destiny2.exe`.

## deploy-mybuild.ps1 — just deploy

Copies your built `steam_api64.dll` + `.pdb` into the game folder (refuses if
the game is running). Generated by `SunriseInstall.ps1` with your paths filled
in; `Sunrise-DevLoop.ps1` does the same deploy inline.

## gen_glossary.py — regenerate the module glossary

Walks `src/`, extracts each header's leading doc-comment, and writes a
searchable HTML glossary plus a markdown one. Python 3, standard library only.

```powershell
python gen_glossary.py src
# -> Sunrise-Glossary.html  and  Sunrise-Glossary.md
```

The glossary is only as good as the doc-comments it reads, so it never drifts
from the code — re-run it after changes.
